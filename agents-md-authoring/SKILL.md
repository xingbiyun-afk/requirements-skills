# 写项目的 AI 入口文档

新会话的 AI 读完它，应该知道三件事：**项目是什么、去哪找权威、怎么干活和验收。** 它不写历史流水账，也不写业务规则。

## 固定骨架（6 段，不增不减）

| 段落 | 写什么 | 正文行数上限 |
|---|---|---|
| 1 项目定位 | 一句话是什么 + 技术栈 + 默认入口 + **当前状态（≤5 行，带日期）** | 10 |
| 2 去哪找权威 | 阅读优先级，**指路不复制**（PRD、接口契约、README、页面事实） | 8 |
| 3 接手顺序 | 第一次读什么、改哪个目录或文件 | 8 |
| 4 验证命令 | 能直接复制的命令 | 6 |
| 5 边界 | 禁入项，以及 Mock 与生产各能证明到哪 | 10 |
| 6 协作门禁 | PR、合并由谁执行、交付流程 | 6 |

**整篇 ≤60 行**（含标题与空行，正文合计约 48 行）。「当前状态」并入第 1 段，不单列成段。**新建的入口文档不含「历史状态」「更新记录」段。**

## 三条硬规则

**① 一条信息只写一处。** 同仓只留一份正文：`AGENTS.md` 与 `CLAUDE.md` 并存时选一份当正文，另一份**只写一行指针**「见 <正文文件名>」加工具差异，stub 里的文件名跟正文走。选哪份由项目定：主用哪个 AI 工具就选它认的那份，两者都用时选 `AGENTS.md`。历史归宿：合并与验收流水 → `CHANGELOG.md`；单次任务过程 → CR / 开发总结 / 日报。业务规则值 → PRD。入口文档只放指针。

**② 不写流水账。** 历史合并过程、逐单验收细节一律不进本文；当前状态压缩到第 1 段的 5 行内。

**③ 边界要能判定。** 每条边界都要能 grep 或看 diff 验证。推荐两种写法：**禁止 / 必须**（「禁止引入 TypeScript / Vue 3」），或**能证明 / 不能证明**（「Mock 通过能证明页面行为，不能证明真实接口、权限与生产」）。字面词不强制，能判定就行；「注意保持代码风格」不合格。

## 整理老文档：先体检再搬

```bash
F=AGENTS.md   # 正文那份；若正文是 CLAUDE.md 就改这里
total=$(wc -l < "$F")
# 历史段行数：按标题层级切段，段内子标题一并计入
awk '/^#+ /{l=length($1); if(l<=sl)inh=0; if($0~/历史状态|更新记录/){inh=1;sl=l}} inh' "$F" | wc -l
# 陈旧状态词只许出现在历史段
awk '/^#+ /{l=length($1); if(l<=sl)inh=0; if($0~/历史状态|更新记录/){inh=1;sl=l}} !inh' "$F" | grep -nE '待合并|未提交|待 PR'
# 第二份入口应是纯指针：状态段数必须为 0
for f in AGENTS.md CLAUDE.md; do [ -f "$f" ] && echo "$f: $(grep -cE '^#+.*当前' "$f") 个状态段"; done
```

**整理存量**：历史段行数 > `total/3` 就整段搬去 `CHANGELOG.md`，本文留一行指针；陈旧词出现在现行段，改成已关闭的事实；第二份入口的状态段数不为 0，按规则 ① 降级成纯指针。

**新建文档**：历史段应为 0 行，这段命中即返工；上面命令只用于体检存量文档。

## 和其他技能的分工

- 文档**内容**怎么写 → `prd-rule-authoring`；一次改动怎么拆成任务 → `change-list-authoring`；本技能只管**入口文档**（骨架、边界、门禁、什么不该写）

## 交付时说明

写了哪份、放哪、为什么；搬了哪些内容、搬去了哪里；历史段行数与占比实测值（按上面命令口径）；同仓若还有第二份入口，如何处理。
