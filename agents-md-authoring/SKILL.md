# 写项目的 AI 入口文档

新会话的 AI 读完它，应该知道三件事：**项目是什么、去哪找权威、怎么干活和验收。** 它不写状态流水账，也不写业务规则。

## 固定骨架（6 段，就这 6 段）

| 段落 | 写什么 | 上限 |
|---|---|---|
| 1 项目定位 | 一句话是什么 + 技术栈 + 默认入口 | 5 行 |
| 2 去哪找权威 | 阅读优先级，**指路不复制**（PRD、接口契约、README、页面事实） | 8 行 |
| 3 接手顺序 | 第一次读什么、改哪个目录或文件 | 8 行 |
| 4 验证命令 | 能直接复制的命令 | 6 行 |
| 5 边界 | 禁入项、Mock 与生产各能证明到哪 | 10 行 |
| 6 协作门禁 | PR、合并由谁执行、交付流程 | 6 行 |

**整篇 50 行以内。** 超过 50 行，基本是掺了不该写的东西。

## 三条硬规则

**① 一条信息只写一处。** 同仓只留一份入口文档：`AGENTS.md` 和 `CLAUDE.md` 并存时选一份当正文，另一份只写「见 AGENTS.md」加工具差异（两处都写状态必然漂移）。状态和历史的归宿是 CR、开发总结、日报和 `CHANGELOG.md`；业务规则值的归宿是 PRD。入口文档只放指针。

**② 不写流水账。** 当前状态不超过 5 行并带日期；历史合并过程、逐单验收细节不进本文。判据：`（历史状态 + 更新记录）行数 ÷ 总行数 ≤ 1/3`，超了就把这部分搬去 `CHANGELOG.md`，本文留一行指针。

**③ 边界要能判定。** 反例「注意保持代码风格」无法验证；正例：「禁止引入 TypeScript / Vue 3」「`src/mocks/` 只在 dev 和 demo 构建启用」「本项目不用 Git，不执行提交和 PR」。每条边界都要能被 grep 或看 diff 验证。

## 写完自查

```bash
F=AGENTS.md; total=$(wc -l < "$F")
awk '/^#+ .*(历史状态|更新记录)/{f=1} f' "$F" | wc -l   # ≤ total/3
grep -nE '待合并|未提交|待 PR' "$F"                       # 只许出现在历史段
ls AGENTS.md CLAUDE.md 2>/dev/null                         # 两份都有一致日期吗
```

占比、陈旧词、双份入口三项都过再交付；有命中就搬走或合并。

## 和其他技能的分工

- 文档**内容**怎么写 → `prd-rule-authoring`；一次改动怎么拆成任务 → `change-list-authoring`
- 本技能只管**入口文档**：骨架、边界、门禁，以及判断「什么不该写在这里」

## 交付时说明

写了哪份、放哪、为什么；哪些内容搬去了哪里；体积与流水账占比的实测数字；同仓若还有第二份入口，如何处理。
