# 写项目的 AI 入口文档

新会话的 AI 读完它，应该知道三件事：**项目是什么、去哪找权威、怎么干活和验收。** 它不写状态流水账，也不写业务规则。

## 固定骨架（6 段，不增不减）

| 段落 | 写什么 | 正文行数上限 |
|---|---|---|
| 1 项目定位 | 一句话是什么 + 技术栈 + 默认入口 | 5 |
| 2 去哪找权威 | 阅读优先级，**指路不复制**（PRD、接口契约、README、页面事实） | 8 |
| 3 接手顺序 | 第一次读什么、改哪个目录或文件 | 8 |
| 4 验证命令 | 能直接复制的命令 | 6 |
| 5 边界 | 禁入项，以及 Mock 与生产各能证明到哪 | 10 |
| 6 协作门禁 | PR、合并由谁执行、交付流程 | 6 |

**整篇 ≤60 行**（含标题与空行，正文合计约 43 行）；超过 60 行基本是掺了不该写的东西。**入口文档不含「历史状态」「更新记录」段**——它们不属于这 6 段。

## 三条硬规则

**① 一条信息只写一处。** 同仓只留一份入口文档：`AGENTS.md` 与 `CLAUDE.md` 并存时选一份当正文，另一份只写「见 <正文文件名>」加工具差异（例如某工具只认某个文件名）。正文选哪份由项目定，但 stub 里的文件名要跟着正文改。状态与历史的归宿：合并与验收流水 → `CHANGELOG.md`；单次任务过程 → CR / 开发总结 / 日报。业务规则值的归宿是 PRD。入口文档只放指针。

**② 不写流水账。** 当前状态 ≤5 行并带日期，放在第 1 段之后或并入第 1 段。历史合并过程、逐单验收细节一律不进本文。

**③ 边界要能判定。** 每条边界只能写成两类句式之一：**禁止 / 必须**（「禁止引入 TypeScript / Vue 3」「本项目不用 Git，不执行提交和 PR」），或**能证明 / 不能证明**（「Mock 通过能证明页面行为，不能证明真实接口、权限与生产」）。「注意保持代码风格」这类既不能 grep 也不能看 diff 的句子不合格。

## 整理老文档：先体检再搬

```bash
F=AGENTS.md; total=$(wc -l < "$F")
# 历史段行数：按标题切段累加
awk '/^#+ /{h=($0 ~ /历史状态|更新记录/)} h' "$F" | wc -l     # ≤ total/3
# 陈旧状态词只许出现在历史段
awk '/^#+ /{h=($0 ~ /历史状态|更新记录/)} !h' "$F" | grep -nE '待合并|未提交|待 PR'
# 双份入口：第二份不该有状态段，或状态日期与正文一致
ls AGENTS.md CLAUDE.md 2>/dev/null
```

占比超过 1/3：把历史段整段搬到 `CHANGELOG.md`，本文留一行指针。陈旧词出现在现行段：改成已关闭的事实。双份入口：按规则 ① 合并成一份正文加一份 stub。

## 和其他技能的分工

- 文档**内容**怎么写 → `prd-rule-authoring`；一次改动怎么拆成任务 → `change-list-authoring`；本技能只管**入口文档**（骨架、边界、门禁、什么不该写）

## 交付时说明

写了哪份、放哪、为什么；搬了哪些内容、搬去了哪里；历史占比的实测数字（按上面的命令口径）；同仓若还有第二份入口，如何处理。
