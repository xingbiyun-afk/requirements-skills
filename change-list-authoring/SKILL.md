# AI 可执行变更清单

## 目标与阅读顺序

把需求写成接手者能执行和验收的任务：明确目标、依据、改动落点、字段与操作规则、文档同步、证据和完成条件。编写或正式化清单不自动授权开发、提交、推送或创建 PR；用户已有的执行授权继续有效。

## 工作流程

1. **确定范围**：确认日期、编号、阶段、参与仓库、只读参考和交付类型。读取项目现有的协作规则、启动说明和文档入口。普通 CR 检查受影响页面及必要的关联入口；全面审查才盘点约定范围内的全部在用页面。
2. **核对现状**：检查分支、工作区、相关合并记录、路由、组件和测试，定位现行 PRD、页面规则及接口契约。分别记录业务规则、代码事实、待核验契约、历史和规划。明确被后续决定替代的旧规则不再作为现行要求；无法确认的冲突列来源、说法、时点和影响，交责任方裁定。审查历史快照只使用截至当时的证据，后续修复不得追认为当时已覆盖。
3. **盘点影响与边界**：逐项标注新增、修改或删除，并追踪同级入口、子页面、弹窗、字段、操作及状态。删除项还要核对旧链接、兼容入口、接口消费者和测试；新增或修改项核对共性规则及关联流程。若改变横向规则、共享字段/状态语义或文档权威结构，按 `rule-and-doc-impact.md` 建影响矩阵（权威位置、受影响文档/消费方、动作、同步时机、验收），并把全量排查作为可选项显式判定。需要深审时按通用审查方法建立矩阵和发现项。
4. **写成任务**：每项用唯一 ID 表达一个可交付结果，列仓库、文件/符号或文档章节、输入与来源、条件、动作、结果、异常及验收。缺信息先补证据；仍无法判断时写问题、影响、责任方、解除条件和依赖。会改变实现方向的未决事项只暂停依赖它的子项，已获授权且不依赖它的工作继续。
5. **组织文档**：沿用项目目录与命名，按标准模板保留核心章节，条件章节按适用性填写。优先更新现行权威正文，复用共性规则和现有索引，不另造竞争性规则。逐文件列修改位置、内容、时机和回链；不改正文也写明理由及需要更新的状态记录。
6. **发布前自审**：按下面的质量门槛复核，并通读受影响文档的术语、衔接、冲突和链接。回报清单路径、审查结论、证据范围及未决项；草案、正式版、实现和验收状态分别说明。

## 质量门槛

- **任务可定位**：每项有明确落点、依赖、产出和客观验收条件。引用“现有逻辑”时给出文件/符号及继承的行为；不能只写“优化一下”或“参考现有页面”。
- **字段有规则**：本次范围内的展示、输入、计算、统计、筛选、状态和业务提示均对应规则正文或共性引用。核对来源、账号/权限、格式/枚举/上下限、默认/空值、必填/可编辑、读写时点、快照或实时及后续变化。统计字段还要说明对象、范围、时间、去重、重置和零值/缺失/失败；未知值不补猜。
- **字典同单同步**：本次代码新增、修改或下线枚举值、状态值或页面可见文案时，所触及业务字典须完整落入现行权威正文，与代码同一 CR、同一 PR 合并；包括顺带发现和小幅收口，不得跨单后补。历史缺字典也须整体补齐，特殊值和兼容值须有业务注释。清单列正文路径、章节、同步时机及验收点；完整范围、登记和双向验收见模板 §8。
- **操作有结果**：逐项写可见、可用、确认、成功、取消、失败、刷新和再次操作。按适用性覆盖正常、空数据和会改变结果的边界；操作链检查中途变更、失败恢复、旧数据、失权、重复与并发，不穷举无业务意义的组合。
- **数据责任清楚**：管理页面、服务提供方、请求/持久化/消费端映射分别说明。缺契约时列技术待核验，不能由菜单或 Mock 推断真实端点、DTO（接口数据字段）、权限及生产能力。
- **证据可复核**：验收点写环境、版本、命令或步骤、预期结果和证据类型。文档、源码、逻辑测试、构建、可见浏览器、自动化、CI、真实接口和生产证据分别记录；跳过或未执行不算通过。沿用项目测试分层，不强制使用某项目的 L0/L1/L3 名称。
- **状态不混淆**：规则完整性、实现一致性、验证结果和任务完成状态分别判断。业务已定但技术契约缺失不标为业务待决定；审查完成不代表发现项已修复。覆盖率须有可核对的分母，页面、字段/操作和场景分别报告，并列未核实、未执行及排除项。
- **文档链闭合**：已确认规则有来源，修改文档有更新记录和有效回链；历史记录标时点。跨端/跨仓只在实际参与时分别登记责任与证据，不能以一端完成代表其他端完成。
- **横向规则有传播**：若改动横向规则、共享字段/状态语义或文档权威结构，`rule-and-doc-impact.md` 的影响矩阵必须覆盖权威落点、实际消费方、双端/多仓、下游摘要/回链和全量排查判定；不得只写代码/页面任务。
- **文档质量可验收**：文档类任务须验收权威唯一、下游摘要+回链、判定/例外可读、术语一致、双端边界、链接与结构；不能只以“文档已改”关闭。
- **文字明确简洁**：关键规则写清主体、条件、动作和结果；复杂条件拆开，同一概念固定名称。共性规则引用一次，不堆叠同义句；删字不改变责任、条件、取值时点或结果。必要技术标识首次出现时说明业务含义。

正式版仍可包含明确列出的未决项，但不得把它们写成已确认需求；其依赖任务须有停止条件。只有达到约定完成定义，才将清单或发现项标为已关闭。
