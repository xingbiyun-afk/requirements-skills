# 变更清单标准模板

沿用项目标题、编号、日期和状态约定。§0–§4、§6–§10 是核心章节；不适用时写明理由，不留空。§5 各矩阵、§3.6 和 §7.5 按适用性保留，复用已有表格时引用其位置。

深审方法见[通用审查方法](review-method.md)。复制模板时删除写作提示，不把技能内部路径写成项目规则来源。

### 8.1 正文落点与常规同步

单仓项目只填写本仓实际影响的文档；若没有跨仓关系，不得为了套模板新增跨仓同步项。不涉及下述字典同步且正文不需改时，写明“不改正文，原因；仅更新哪份登记/状态”。
先确定现行权威 PRD、页面规则和接口契约的正文位置；沿用索引/追溯文件的导航或门禁用途，避免新建平行规则正文。
更新后按读者路径通读整篇，检查标题、段落衔接、重复/冲突与中文术语；必要的技术标识首次出现时解释业务含义。

### 8.2 枚举、状态与文案字典同单同步

本次代码中凡新增、修改或下线枚举值、状态值、页面可见文案（含提示语、空态、操作结果），无论主需求、顺带发现或任务表未点名的小改，都须与代码在同一 CR、同一 PR 中更新现行权威正文，不得代码先合并、文档跨单后补。正文落点可为 PRD、主页面规则明细或接口契约；沿用权威位置，不复制平行字典。

“完整字典”指本次触及的业务字典整体，不是全系统所有字典：列齐代码值与展示值、业务含义、各自产生条件、展示文案、适用场景及权限范围。文案含动态内容时写模板、变量含义和来源；状态还须说明允许的转换、触发条件和结果。原正文缺字典时，本次须整体补齐，可标整理时点；未知项核实或交责任方裁定，不猜填，也不以“历史欠账”留半套字典。未补齐前不得将该项标为可合并。

在上表显式列出字典的正文路径、章节和更新时机（与代码同 PR 合并），并将完整性列为验收点。代码中的特殊值、遗留兼容值须用注释说明业务含义及适用条件，与正文一致。

双向验收：逐一追踪 diff 中的枚举/状态/文案变化到正文字典条目，再逐值核对正文字典与当前实现的条件、文案和场景。现行值无遗漏、无多余；已下线或仅为兼容保留的值单独标明状态与适用边界，并核对是否仍有兼容处理，不能混列为现行可用值。记录证据位置；此核对不代替行为测试或真实接口验证。

### 8.3 横向规则与文档结构变更

本次改动若涉及横向规则、共享字段/状态语义或文档权威结构，按 `rule-and-doc-impact.md` 填写影响矩阵（可增行/减行，不适用写理由）：

| 编号 | 规则/字段/结构 | 现行权威位置 | 受影响文档/消费方 | 本单动作 | 同步时机 | 验收 |
|---|---|---|---|---|---|---|
| I-01 |  |  |  | 完整改写 / 摘要+回链 / 只登记 / 待承接 | 同 PR / 后续 | 检查点+证据 |

要求：一行一个可独立验收的变更；权威位置具体到文档+章节；实际消费方不虚构；同一规则只允许一处完整改写，其他位置降级为摘要+回链。若判定需要同类全量排查，须写分母、问题类型、记录字段和验收；小改不强制。
