# 历史写作示例（结构借鉴）

以下只提供可复用的**结构、粒度和验收思路**，不是现行规则、实现或项目模板；不得把示例中的项目名、路径、业务值、状态或验收结论照搬进新的 CR。

## 可借鉴的清单结构

| 场景 | 可借鉴之处 | 使用时补什么 |
|---|---|---|
| 阶段迁移 | 范围/非范围、过渡路径、旧入口保留与删除、测试与文档影响 | 本次实际路由/入口、数据源、回滚与双实现漂移控制 |
| 字段/基线归集 | 字段级基线、测试资产与文档归集、证据分层 | 本次字段清单、权威落点、未覆盖项 |
| 视觉/运行时修复 | 把视觉要求写成运行时可观察的几何/滚动/交互验收，而不是只列 CSS | 具体浏览器、视口、遮挡/滚动断言与证据 |
| 文案/校验型 | 逐条枚举用户可见文案、校验条件、错误态和恢复路径 | 本次实际文案来源、字典权威、触发条件 |
| 权限/数据范围 | 角色、可见范围、读写时点、越权与失权表现分开写 | 本次权限模型、数据权限来源、待核验契约 |

## 借鉴时的通用要求

1. **只借结构，不借结论**：示例中的业务值、状态、阈值、目录、项目名不得直接复制。
2. **先找现行权威**：新 CR 必须引用当前 PRD/页面规则/契约，不能把历史 CR 当规则依据。
3. **补足分母**：示例若只覆盖部分页面，新 CR 要写清纳入范围、排除理由和未核实项。
4. **区分证据**：文档、源码、逻辑测试、构建、可见浏览器、CI、真实接口分别记录；示例中的“已验收”不能作为本单证据。
5. **可访问性**：示例文件不可访问时跳过，不把示例路径写入新清单。

## 迁移类特别要求

迁移清单必须回答：旧页面何时保留、何时仅作兼容、何时删除；新页面的唯一入口和返回协议；数据源是否统一；存在跨仓关系时哪份文档是权威；迁移期间如何避免双实现漂移。不要把“新壳已建立”误写成“全部页面已迁移”。

## 审查型清单特别要求

审查型 CR 的示例只借鉴“发现 ID + 条件 + 预期/实际 + 证据 + 责任/依赖 + 关闭依据”的闭环格式；不得复制历史发现项或把它当作当前缺陷。审查完成与发现项修复分别验收。
