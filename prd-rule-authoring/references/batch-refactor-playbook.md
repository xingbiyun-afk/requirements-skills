# 批量重构手册（多篇文档一次改造）

## 1. 适用

把 N 篇既有规则正文重构为阅读层，或按新体例批量升级既有阅读层。

## 2. 阶段

| 阶段 | 产出 | 关键控制 |
|---|---|---|
| 0 准备 | 权威正文清单、文档映射、缺口清单 | 确认读者与范围；不清权威正文不动手 |
| 1 样板 | 1 篇定稿样板（含元信息、待确认事项） | 用户确认体例与详细度；样板即基准 |
| 2 分批 | 按模块/目录切分，每批 5~9 篇 | 分批评审，避免一次性全量返工 |
| 3 写作 | 并行或顺序产出 | 每篇先盘点源章节→缺口清单→重写→自检 |
| 4 集成 | 合并、统一标题/命名/元信息 | 负责人统一术语与格式 |
| 5 验收 | 机械检查 + 抽读 + 双轨一致性 | 见 quality-checklist |
| 6 收口 | 索引/入口/台账按项目流程更新 | 不把“入口实现”写进本技能范围 |

## 3. 分工建议

- 每批 1 名集成负责人（统一体例、术语、命名）；
- 写作者每人负责 2~5 篇同模块文档，减少跨模块口径冲突；
- 阅读层与权威正文的同步检查由集成负责人做；
- 用户负责样板确认与关键口径裁定，不承担逐篇校对。

## 4. 常见风险与对策

| 风险 | 对策 |
|---|---|
| 体例不统一 | 样板先定稿；集成负责人最后统一 |
| 规则值被改写 | 抽样对照 + 缺口清单；发现冲突回权威正文 |
| 技术细节残留 | 机械禁词检查 + 集成负责人复查 |
| 未定被抹平 | 待确认事项表强制保留；正文【待确认】标记 |
| 文档负责人缺失 | 头部元信息模板必填；未知填“待指派（角色）” |
| 历史混入正文 | 禁词检查；历史只留权威正文/CR/git |
| 批量返工 | 每批先交 1 篇给用户预看，再推其余 |

## 5. 交付节奏建议

1. 样板定稿（用户确认）；
2. 批 1 全量交付 + 用户抽读；
3. 批 2、批 3 按同体例推进；
4. 全部完成后统一机械检查与索引收口。
