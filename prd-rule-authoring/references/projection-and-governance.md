# 投影方法与双轨治理

## 1. 投影：从规则正文到阅读层

阅读层不是删减版规则正文，而是**按读者重建**的信息结构。

### 1.1 先盘点源文档

列出源正文的章节，逐节标记：

| 源内容 | 处理 | 说明 |
|---|---|---|
| 业务目标/背景/术语 | 压缩 | 只留理解页面所需的最小背景 |
| 页面结构与操作流程 | 保留 | 重排为读者路径 |
| 字段/列表/查询/操作规则 | 保留 | 去掉实现细节，保留业务口径 |
| 权限/数据范围 | 保留 | 系统现有规则类一句话带过；未定进待确认表 |
| 状态/枚举/文案 | 保留 | 只列展示值与业务含义；完整字典留在权威正文 |
| 异常/空态/失败 | 保留 | 只写用户可见反馈 |
| 验收标准 | 保留/重写 | 业务可验证点，不写测试编号 |
| 实现/Mock/代码路径/行号/DTO | 删除 | 留在权威正文 |
| 更新记录/历史快照/已废止注记 | 删除 | 阅读层不呈现历史 |
| 变更编号（CR/需求单） | 删除 | 可追溯性由权威正文/CR/git 承担 |
| 重复表述/沿革解释/假设推演 | 删除 | 一条规则只留一个结论 |

### 1.2 重建骨架

按 `product-requirements-spec.md` 的骨架重排，不保留源文档章节顺序。

### 1.3 缺口清单（写作前置）

写作前把源文档中的模糊点分为四类：

| 类别 | 含义 | 处理 |
|---|---|---|
| 已确认 | 权威正文有明确规则 | 直接落文 |
| 仓内留底 | 权威正文/历史裁定已有结论但未集中在当前章节 | 引用留底结论，注明依据 |
| 待确认 | 真正的业务未定 | 进阅读层「待确认事项」，不得猜填 |
| 技术待核验 | 接口/契约/实现细节未定 | 不进阅读层正文；属于系统边界时写「按系统现有规则」或另立技术待办 |

缺口清单逐条交责任方确认；确认一条落一条，未确认项在阅读层如实标注。

### 1.4 投影自检

- 行数：≤权威正文 50%，目标 15~30%；
- 规则值零变化：抽样 3~5 处关键规则与权威正文对照；
- 条件不丢：原文的条件、例外、取值时点、结果不得被“压缩”掉；
- 原因/条件清单完整：先记录权威条数，再逐项核对阅读层覆盖；允许按同一修正动作合并，差集为 0；
- 未定不漏：所有未定项进待确认表；
- 技术细节零命中：按 quality-checklist 的禁词检查。

## 2. 双轨治理

### 2.1 权威分工

| 层 | 定位 | 权威性 |
|---|---|---|
| 规则正文 / PRD / 契约 | 规则值、字段、状态、接口责任 | **权威** |
| 阅读层（产品需求说明书） | 读者投影 | 重述，不新增/修改规则值 |
| 模块总览/索引 | 导航 | 不定义规则 |

### 2.2 同步触发

| 变化 | 更新范围 |
|---|---|
| 规则值、权限、状态、枚举、文案变化 | 权威正文 + 阅读层（同单） |
| **数据来源、存储形态、读写边界、会话/生命周期变化**（如“只读样本”改为“运行时共享会话可写”） | 权威正文 + 阅读层 + 技术真源对照表 + 代码中的口径注释（同单） |
| **样本数量、枚举覆盖面变化**（如日志条数、类型数调整） | 权威正文 + 技术真源表 + 测试台账（同单） |
| 仅表达精简、章节调整 | 仅阅读层 |
| 阅读层发现权威正文缺失/冲突 | 先补权威正文或登记 CR，再更新阅读层；不得只在阅读层“修正” |
| 未定项转已定 | 权威正文 + 阅读层正文 + 待确认表状态 |

### 2.2.1 横向规则的投影

同一规则被多个消费侧重不同的页面/端消费时，先区分权威正文与消费方（规则包结构、判定结构与反模式见 `cross-cutting-rules.md`；本节只讲投影分工）：

| 投影对象 | 应写什么 | 不应写什么 |
|---|---|---|
| 管理/配置页 | 完整定义、字段、判定顺序、字典、例外/终态 | 只留一句概括 |
| 发起/交易页 | 来源、读取时点、对选择/提交的影响、例外、回链 | 复制完整配置规则 |
| 详情/审计页 | 展示时点、快照/实时、只读边界、异常/终态 | 重新定义规则 |
| 另一端/另一仓 | 消费方式、差异、待承接、只读参考 | 默认另一端已同步 |

投影前先确认每个实际消费方；不存在的端不虚构。双端/多仓只在一个权威位置维护规则值，另一端写消费差异与待承接，不以一端完成代表另一端完成。

### 2.3 冲突裁定

1. 最新 CR/用户裁定；
2. 现行权威正文；
3. 阅读层；
无法判断时交责任方，不以“历史写法”或“实现现状”代替裁定。

### 2.4 漂移检查（交付前）

- 抽样 3~5 个关键枚举/状态/权限/边界，对照权威正文与阅读层；
- 阅读层出现权威正文没有的规则值 → 视为缺陷；
- 权威正文变更但阅读层未更新 → 视为双轨失同步，登记修正。

### 2.5 责任

文档负责人对双轨同步负责；阅读层文档头写明负责人与变更处理入口；变更发生时由负责人决定是否需要重写投影。
