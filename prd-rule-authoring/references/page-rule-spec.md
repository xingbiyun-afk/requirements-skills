# 规则正文（PRD / 页面规则明细）写作规格

规则正文是开发与测试的**权威依据**：必须能定位、能执行、能验收。

## 1. 核对依据与落点

- 读项目协作入口、现行 PRD、页面规则、字段/接口契约、索引与测试追溯；核实现状时才看代码。
- 分别记录：已确认业务规则、当前实现事实、技术待核验、历史记录、未来规划。
- 历史内容不一定失效：核对是否已被后续决定替代；已被替代的旧口径不再作为现行要求。
- 来源冲突：列说法、时点、影响，交责任方裁定；不得自行融合。
- 落点选择：整体 PRD（目标/范围/角色/对象/跨页流程）→ 页面规则明细（入口/字段/操作/状态/异常）→ 契约（数据模型/服务职责）。

## 2. 功能路径与影响面

- 入口 → 同级入口/按钮/标签 → 下级页面/弹窗/提示 → 操作 → 结果。
- 关联流程与共性规则；删除项追旧链接、兼容入口、历史记录、接口消费者与测试。
- 新功能无代码时按已确认需求与设计写，标明规划状态。

## 2.1 横向规则与多消费方

同一规则影响多个消费侧重不同的页面/入口/端时，先按 `cross-cutting-rules.md` 建规则包：唯一权威、完整字典、判定顺序、例外/时点、消费方矩阵。规则正文负责权威完整；下游页面只写来源、使用影响与例外，并回链权威，不复制平行全文。单页规则不强制套用。

## 3. 完整性矩阵（按适用性取用）

| 内容 | 写清什么 |
|---|---|
| 字段 | 名称/含义、来源、账号/权限、类型/格式/单位、默认/空值、必填、枚举、精度/上下限、联动、可编辑条件 |
| 统计与计算 | 公式、对象、范围、时间、去重、重置、零值/缺失/失败、对关联数据的影响 |
| 操作 | 角色、可见/可用条件、确认、成功结果、取消/失败、刷新、再次操作 |
| 数据生命周期 | 产生者、更新者、持久化责任、读写时点、快照或实时、旧数据表现 |
| 接口责任 | 页面维护对象与服务端职责、请求/响应/详情映射、错误与重试；缺证据的端点/DTO/权限列技术待核验 |
| 枚举/状态/文案字典 | 本次触及的整组字典：值（代码值/展示值）、含义、产生条件、文案、场景/权限、转换条件与结果 |
| 路由/返回/兼容 | 多入口、深链、返回目标、旧入口兼容、跨端映射 |
| 提示与异常 | 阻断/警示分层、失败恢复、空态/加载态/错误态 |
| 验收 | 身份+前置数据、操作、预期页面/数据结果；可转成可执行验收条件 |

## 4. 字典规则

- **写完整字典，不只写改动项**；字典=本次触及的某一组业务值（一组枚举/一个状态机/一类文案），不是全系统。
- 字典只在一处权威成文；其他位置引用。
- 已下线/兼容保留值单列，标明状态与适用边界，不混入现行值。
- 接收 CR 字典改动时逐值落回权威正文，不留在 CR 或代码注释里。

## 5. 场景选择

先正常、空/缺失、非法/边界、失败；再按风险选：单条/多条、相同/不同对象、改选/清空、旧数据、失权、来源变更、超时、重复、并发、部分成功。不穷举无意义组合。

跟踪对象变化：未保存输入 → 已保存 → 历史快照 → 外部变化后复核 → 失败恢复 → 再次操作。多对象分别写结果与恢复范围；区分打开页面、请求受理、业务完成。

## 6. 未决与证据

- 规则完整性、实现一致性、验证结果分别判断。
- 缺契约→技术待核验；业务未定→交业务方；缺运行证据→标未验证；不能用代码/Mock 反推业务决定。
- 未决项写位置、条件、预期/实际、依据、责任、解除条件、阻断范围；只暂停依赖项。

## 7. 编辑与自审

- 结论先行；同一概念固定名称；业务、实现、历史、规划分开表述。
- 不用“优化一下”“参考现有页面”代替规则；引用现有逻辑要给出文件/符号与继承行为。
- 通读：大纲、衔接、术语、重复/冲突、更新记录、链接。
- 从开发与测试视角确认：能找到要实现的行为；能逐字段找到条件、预期与边界。
