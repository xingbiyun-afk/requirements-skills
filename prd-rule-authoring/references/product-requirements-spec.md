# 产品需求说明书（阅读层）写作规格

阅读层是权威规则正文的**读者投影**：让产品、开发、测试接手快速理解「这个页面/模块要什么、边界在哪」。它不是验收依据，也不新增规则值。

## 1. 前置条件

- 权威正文已存在（规则明细/PRD/契约）。缺权威时：先补权威，或在文档中标注缺口；**不得凭印象编造规则**。
- 阅读层与权威正文的关系在文档头写明（依据版本/日期）。

## 2. 文档头元信息（必须）

```
适用页面：<页面/模块>
依据：<权威正文名称与版本/日期>
文档负责人：<角色/负责人>（负责口径变更与读者答疑）
口径维护人：<角色/团队>
变更处理：<如何提变更、找谁确认>
```

## 3. 骨架（按页面裁剪）

1. **页面概述**：定位、使用场景、本页不做；
2. **用户与权限**：菜单可见、数据可见范围、导出/操作范围；系统现有规则类一句话带过；
3. **页面结构**：查询/操作/列表/分页/状态提示；
4. **规则**：按页面类型分节（查询条件、列表字段、操作规则、字段与校验、流程步骤等）；
5. **状态与操作**：状态含义、处理人/操作人、可用操作；
6. **异常、空态与加载**：用户可见反馈；
7. **验收标准**：业务可验证点（身份+前置数据+操作+预期）；
8. **不在本页范围**：边界与占位；
9. **待确认事项**（必须，见 §4）；
10. **口径说明**：本文未展开项按系统现有规则执行的声明（不得用于掩盖未定）。

模块级文档骨架：模块定位 → 页面与文档索引 → 阅读顺序 → 跨页流程与规则 → 权限与范围 → 范围边界 → 待确认事项 → 口径说明。

**横向规则**：跨页面/跨端共用的规则可在阅读层保留摘要或判定表，但必须回链权威正文；阅读层不复制完整规则、不新增或修改规则值。管理/配置页与发起/交易页的侧重不同，按 `cross-cutting-rules.md` 的消费方矩阵取舍。

## 4. 待确认事项（阅读层核心规则）

**必须保留**，不得省略、不得把未定写成已定、不得用「按系统现有规则」含混过去。

| 编号 | 问题 | 影响 | 需谁裁定 | 当前状态 | 读者动作 |
|---|---|---|---|---|---|
| Q-01 | （具体未定内容） | （影响哪些规则/页面/验收） | 业务/产品/技术 | 待裁定/核验中/待评估 | 向文档负责人提出变更或等待更新 |

- 正文中出现未定内容时标注【待确认】，并在表中汇总。
- 未定转已定后：更新正文 + 更新表状态；阅读层**不写变更叙事**。
- 没有未定项时写「暂无」。

## 5. 「按系统现有规则」的使用边界

**可以使用**：数据权限范围、组织取值时点、导出上限/失败处理等已明确由系统既有能力承接、且不需要产品再裁定的口径。

**不可使用**：真正未定的业务选择（如角色平台范围、订单结果语义、状态定义）。必须进待确认表。

## 6. 文体与禁用内容

- 结论先行；一句话能说清不展开；每条只表达一个结论。
- 中文用户语言；英文 UI 术语改中文（如 hover→鼠标悬停、checkbox→勾选框）。
- 禁用：实现/接口/DTO/Mock/代码路径/文件后缀/行号/函数名、CR/RT/需求编号、更新记录/变更历史/历史快照/已废止注记、像素阈值、元写作说明行（如「本文不写…」自指句）。
- 不写变更叙事；可追溯性由权威正文 + CR + git 承担。
- 每次修改只更新现状与待确认表状态，不追加历史段落。

## 7. 长度与粒度

| 类型 | 上限 | 目标 |
|---|---|---|
| 页面阅读层 | 权威正文 50% | 15~30% |
| 模块业务需求说明 | — | 200~400 行 |
| 模块总览与索引 | 100 行 | 40~80 行 |
| 范围说明页（非 MVP/占位） | 40 行 | 20~35 行 |

## 8. 自审（摘要）

- 骨架完整、章节顺序合理、无重复章节；
- 每个结论都能在权威正文找到依据；无新增/修改规则值；
- 未定项全部进待确认表（含负责人/裁定方/读者动作）；
- 禁用内容零命中；H1=文件名；链接可达；行数达标；
- 抽读 3~5 处关键规则与权威正文一致。
