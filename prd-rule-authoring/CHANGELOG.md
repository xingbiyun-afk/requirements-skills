# prd-rule-authoring 技能升级记录

## v2.1（2026-11-02）

### 背景

v2 已覆盖规则正文/阅读层/双轨治理，但在大型项目中，同一规则常被多个页面、入口或端共同消费（配置页、发起/交易页、详情/审计页、Web/App）。实际写作中容易出现两种问题：规则散落在多份文档，或为“精简”把多条件判断压成一句，导致下游读者无法一次看全、不同文档口径漂移。该问题与具体业务领域无关，属于横向规则的通用写作问题。

### 变更

- **新增横向规则模型**：`references/cross-cutting-rules.md`，定义规则包、唯一权威落点、消费方矩阵、判定结构、例外/时点、双端/多仓处理、同类全量排查与反模式。
- **SKILL.md 增加 §2.1**：识别横向规则；管理/配置页写完整规则，发起/交易页写来源+使用+影响+例外，详情/审计页写展示时点与只读边界，另一端写消费差异/待承接；小需求不强制全量审查。
- **规则正文与阅读层**：`page-rule-spec.md` 增加横向规则入口；`product-requirements-spec.md` 明确阅读层摘要 + 回链、不复制完整规则；`projection-and-governance.md` 增加横向规则投影与消费方矩阵。
- **自审**：`quality-checklist.md` 增加横向规则检查项（唯一权威、消费方覆盖、判定完整、双端边界、全量排查分母）。
- **可读性约束**：多条件/例外拆编号或表格；同一概念固定名称；不因简短删条件，也不因完整复制全文。
- **验收修订（2026-11-02）**：横向规则触发条件收紧为“≥2 个消费侧重不同的页面/入口/端”，避免把同字段的列表/详情展示误判为横向规则。

### 兼容性

- 单页规则仍按 `page-rule-spec.md`，行为不变；
- 只有横向、跨端、跨仓或用户反馈“多处说不清”时启用规则包/消费方矩阵/全量排查；
- 阅读层原有规则不变，新增“横向规则摘要 + 回链”要求。

### 来源与验证

- 实践来源：某多页面/多端项目中某一业务标识从配置页到交易页、详情页及另一端的规则散落与压缩问题（不绑定具体业务名称；技能只保留通用模式）；
- 验证：以该实践为回归样例检查能否生成唯一权威段、消费方矩阵、双端差异与全量排查记录；由独立模型验收。


## v2（2026-10-23）

### 背景

在「需求文档产品化精简」项目中，既有 skill 只覆盖规则正文（开发/验收视角），无法表达：
阅读层（产品需求说明书）、阅读层与规则正文的双轨维护、未定事项呈现、页面内阅读入口的边界。

### 变更

- **新增文种选择**：规则正文 / 产品需求说明书（阅读层）/ 模块总览与索引 / 字段接口契约；SKILL.md 增加决策表。
- **新增阅读层规格**：骨架、元信息、文体、长度预算、禁词、历史策略；明确「阅读层是读者投影，不新增/修改规则值」。
- **新增未定事项规则**：阅读层必须保留「待确认事项」表（问题/影响/裁定方/状态/读者动作）与【待确认】标记；不得用「按系统现有规则」掩盖未定。
- **新增双轨治理**：权威分工、同步触发、冲突裁定、漂移检查、文档负责人责任。
- **新增投影方法**：从规则正文到阅读层的删/留/压缩规则与缺口清单分类。
- **新增质量清单与批量手册**：机械检查、可读性抽读、双轨一致性、批量重构阶段与风险。
- **边界解耦**：页面内阅读入口/查看器/构建/搜索属于独立技能 `requirements-docs-viewer`，本技能不涉及。
- **v1 内容保留**：原规则正文写作要求整理进 `references/page-rule-spec.md`；v1 SKILL.md 原文保留在 `archive/v1-skill-20261023.md` 供回溯（不加载）。

### 兼容性

- 只写规则正文的任务：按 `page-rule-spec.md` 执行，行为与 v1 等价；
- 新增阅读层任务：按 `product-requirements-spec.md` 执行；
- 两模式可组合，但阅读层不得替代规则正文的验收职责。

### 来源与验证

- 实践来源：某交付项目的阅读层批量重构与双轨维护；
- 验证方式：成文对照（篇幅比例、禁词/历史/断链零命中）+ 用户口径确认（待确认事项保留、入口解耦、文档负责人）。
