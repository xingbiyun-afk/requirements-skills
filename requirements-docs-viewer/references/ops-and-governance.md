# 运维与治理

## 1. 文档更新流程

- 文档变更 → 重新构建部署后生效（静态复制方案）；如需免构建，另评估运行时服务化方案，不混用。
- 文档负责人对内容负责；入口维护人对映射/构建/渲染负责。
- 更新后跑产物一致性校验与最小回归（历史过滤、搜索、懒加载）。

## 2. 映射维护

- 新增页面/动作页 → 在映射注册表加行；构建校验会拦住缺失/孤儿。
- 文档改名/移动 → 同步更新映射与文档树标题；不做隐式重定向。
- 归档/讨论稿不进入映射；排除口径写在映射注册表注释与构建校验中。

## 3. 生产暴露面

- 入口开关只控制按钮；文档静态资源必须单独防护（排除产物目录或服务端鉴权）。
- 对外演示/交付前确认暴露面处置状态；未处置不得宣称可对外交付。
- 在项目生产接入门禁中登记：处置方式、责任人、验证方式。
- 若文档目录随站点公开部署：评估搜索引擎收录风险（robots/noindex 或纳入鉴权范围），文档 URL 不外贴到公开渠道。
- 文档更新后的缓存：静态复制方案配合缓存策略（短 max-age 或内容 hash 文件名），避免用户看到旧文档还以为已更新。

## 4. 性能与容量

- 启动零文档请求；打开后才加载。
- 文档数量增长时关注：首开等待、搜索索引耗时、内存缓存（可设上限/LRU）。
- 大文档/大量文档可分批加载与受限并发；索引失败可重试。

## 5. 兼容与变更

- 渲染器语法扩容时先补测试与文档说明，避免历史文档降级显示。
- 目录/搜索/历史过滤共享同一解析结果，避免三处逻辑分叉。
- 文档层与入口层解耦：写作技能可独立升级，入口只依赖路径与 Markdown 约定。

## 6. 扩展边界（预留，不实现）

未来能力按以下边界扩展，不破坏现有红线：

- **分级阅读/权限**：给映射条目加可见性字段（角色/密级），在文档树与搜索索引建立**之前**过滤；权限判定不进渲染器，渲染层保持纯函数。
- **多语言文档**：映射路径按语言维度扩展（如 `需求说明书/en/…`），URL 构造与双向校验同源扩展；目录按语言分组。
- **在线编辑/评论/审批**：超出本技能范围，属文档系统能力；若接入，运行时读方案须重新评估（不再适用纯静态复制），与 §1「不混用」冲突时以新方案立项。
- 任何扩展不得违反两条硬红线：**启动零文档请求**、**受限渲染全转义**。

## 7. 状态与证据纪律（验收与收尾通用）

来自 2026-10 阅读窗口两轮验收的教训，适用于本技能承接的实施/收尾/验收记录：

- PR 未合并不得写「已关闭/已合并」：类型用「实施完成（待合并）」，合并 + main run 回填后再转正；
- main run 证据不得错挂：旧 run 属于当时基线（如旧 run 的 L1 计数），新基线只有本地/PR 实跑时须明示「main run 待登记」；
- 行数/用例计数用 `git diff main --numstat` 实数，不凭印象；
- 文档改动超清单授权范围时，补登记而非默认可过。
